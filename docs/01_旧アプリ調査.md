# 01. 旧アプリ（シフト作成サポート）調査メモ

調査日: 2026-11-11 ／ 対象: `archive/shift-app-v1/`（退避前は `main` の `efffa80`）

## 1. 概要

| 項目 | 内容 |
|---|---|
| 目的 | 月単位で「現場（会期）」にスタッフを**自動割当て**するシフト作成ツール |
| 構成 | React 18 + TypeScript + Vite 6、Firebase（Google 認証 + Firestore）、ExcelJS、vitest |
| 規模 | `src/` 約 52 万字。うち取込系（CSV/Excel/ウィザード）と現場管理で過半 |
| 利用状況 | 現在は誰も使っていない（依頼者からの情報） |

## 2. データ構造（`src/types.ts`）

| 型 | 主なフィールド | 新アプリでの扱い |
|---|---|---|
| `Staff` | 氏名、勤務可能曜日、希望休、月間上限日数、最大連勤、NG相手、希望現場 | **氏名だけ引き継ぐ考え方**。制約系は自動割当て用なので不要。新たに時給・交通費を持つ |
| `WorkSite` | 1日×1現場の行。会場名の正規化キー群（`normalizedSiteKey` 等）、取込元情報、会期ID、必要人数、優先度 | 引き継がない。新アプリは「案件＝会場×期間×コンテンツ」を1レコードで持つ |
| `ShiftAssignment` | `siteId` → `assignedStaffIds[]`、不足人数 | 引き継がない。新アプリは人が選ぶ配置（日付・時間・単価つき） |
| `ImportLog` | 取込バッチの履歴 | 引き継がない（取込機能なし） |

## 3. 画面構成（`src/App.tsx`）

ヘッダー（最終更新・同期状態・オンライン表示・Undo・ログイン）＋タブ6枚＋対象月バー。

| タブ | 内容 | 新アプリ |
|---|---|---|
| ダッシュボード | 月の集計・操作ログ | 案件一覧（売上・費用・利益・警告数つき）に置き換え |
| スタッフ管理 | カード型フォーム | 表計算風グリッドのマスタに置き換え |
| 現場管理 | 現場・会期の登録 | 「会場」マスタ＋「案件」に分解 |
| シフト作成 | 自動割当て＋手動調整モーダル | **引き継がない**（人が配置表から選ぶ） |
| 出力 | CSV / Excel | 配置図 PDF に置き換え |
| インポート | CSV / Excel 取込ウィザード | 引き継がない |

## 4. Firestore 同期の方式

- パス: `teams/intention-dev/appData/{staff|workSites|assignments|importLogs}`。**1キー＝1ドキュメント**に配列を丸ごと保存（`{ items, updatedAt, updatedBy }`）。
- `useFirestoreSync`:
  1. localStorage と Firestore の**二重書き**（未ログインでも動く）
  2. **初回 snapshot 到着まで書き込みをブロック**（ログイン直後に手元の古いデータで上書きしない）
  3. `hasPendingWrites` の snapshot は無視。受信直後の保存は `fromFirestore` フラグで1回スキップ
- 競合は**後勝ち（配列ごと上書き）**。`serverUpdatedAt` で他ユーザーの保存を検知する仕組みはある。
- 付随機能: プレゼンス（30秒 heartbeat）、編集中表示、操作ログ（TTL 90日）、直前操作の Undo。
- ルール（`firestore.rules`）: ログイン済みユーザーに `teams/intention-dev/**` を許可、他は全拒否。

## 5. 引き継ぐ設計・引き継がない設計

**引き継ぐ**
- Firebase 初期化（未設定なら無効化して単体動作）と Google 認証（`firebase.ts` / `AuthContext` / `AuthButton` をそのまま流用）
- 同期の3原則（二重書き／初回 snapshot まで書かない／自分のエコーで巻き戻さない）
- チームパス `teams/intention-dev/` と既存ルール（**ルール変更・デプロイ不要**で新データを置ける）
- 純関数をテストする方針（vitest・node 環境）
- 旧データの欠損を補う hydrate 方式

**改める**
- 配列丸ごと1ドキュメント → **案件は1案件＝1ドキュメント**（別々の案件を同時に編集しても互いに上書きしない。1MB 上限も回避）
- エコー判定をフラグ方式 → **`updatedAt` の新旧比較**（ドラッグなど連続編集中に巻き戻らない）

**引き継がない**
- 自動割当て（`shiftGenerator`）、CSV/Excel 取込・会場名の正規化、Excel/CSV 出力
- プレゼンス・編集中表示・操作ログ（土台には入れない。必要になった時点で `archive` から移植可能）

## 6. 旧データへの影響

新アプリは `teams/intention-dev/workshopData/*` と `workshopProjects/*` だけを読み書きし、旧 `appData/*` には触れない。旧アプリは `archive/shift-app-v1/` で単体起動できる（同フォルダの README 参照）。
